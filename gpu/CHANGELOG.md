## [Unreleased]
### Added
* Batch device support (`batch`): a batch session takes the device backend exclusively. Ordinary MSM, transform and quotient calls hold shared admission for their whole call and decline with the reason `batch` while a session is active; the batch entries serve only workers that the session admitted. Beginning a session runs the request boundary and its erasure check first and returns a typed error (busy, erasure failed); it waits only for ordinary calls already in flight to finish. After every batch MSM the registered MSM contexts are evicted and the erasure counters checked, and after every batch transform or quotient the shared scratch, bounce and read-back buffers are released through the wipe path, on unwind too. Registrations displaced during a session are released at its close and counted; device queries, mode changes and administrative calls decline during a session. A panic of a batch device operation is recorded as `operation-panic` and fails the session, and so does a release of an MSM context that the device owner did not confirm; such a release during ordinary proving is recorded in the sticky erasure count that the request boundary and the next session check. The session's wave and final erasure results are returned to the caller
* `midnight-gpu`: CUDA kernels for the `midnight-proofs` accelerator hooks (feature `gpu`): BLS12-381 G1 MSM and NTT through vendored sppark templates (with the small patches listed in `third_party/sppark/PATCHES.md`), and the quotient (coset transforms, numerator over the prover's lowered flat evaluators with permutation, LogUp and trash terms, division by the vanishing polynomial, extended inverse transform), whose extended values stay on the device: only the quotient coefficients come back to the host
* Registered SRS tables (`register_srs`, exact and prefix slices, stale-content check) and resident proving-key copies (`register_key`)
* Erasure of every device and host buffer that held witness values, with a check mode that counts the non-zero words of each zeroed device region on the device (`wipe`), and page-locked staging of large copies (`xfer`)
* Feature `cuda` compiles the CUDA core when `nvcc` is found (`MIDNIGHT_GPU_ARCHS`, default sm_80, sm_86, sm_89, sm_90, sm_100, sm_120 and PTX of the newest); without `nvcc` the crate builds a stub that declines every device call. Feature `test-fault` adds fault injection.
* Service API: `declines()` counts every decline by class and reason label (`no-device`, `below-min-k`, `shape`, `unreduced`, `memory`, `fault`, `device-error`), early declines included; `reset_stats()`; `begin_request()`, `evict_tables()` and `end_request_report()`, which returns the erasure statistics or an error when a check fails
* Hardening of the CUDA core: a free of an sppark block zeroes it, confirms the zeroing (device synchronisation, and in check mode a count of its non-zero words on the device) and the free; a block whose zeroing or free fails is kept in quarantine, counted as a sticky erasure failure and retried by `end_request`. MSM contexts that fail to build release what they allocated; `~msm_t` no longer throws. Transforms of size 1 or above `2^28` are refused at the boundary. The bounce and read-back buffers are kept, not freed, when their zeroing check fails
* Local sppark patches, listed in `third_party/sppark/PATCHES.md`: a point set to infinity is zeroed whole (`ec/xyzz_t.hpp`: no bucket record keeps an earlier MSM's coordinates on a reused context), no-throw `~msm_t`, the host bucket sums, partial sums and row integrals zeroed on every exit, and the bucket-row copies counted (`xfer::CopyStats::msm_d2h_copies`)
* `device_count()` and `context_active()`: detection makes no CUDA context
* `quotient::need_bytes`: the device bytes of a quotient job from its shape, the arithmetic of the job's memory check; `GpuInfo` reports the CUDA runtime and driver versions
* `wipe::Plain` (sealed) and `wipe::Wiped`: `wipe::zero` takes only plain limb and integer types; the masked MSM scalars are zeroed on every exit
* `quotient::set_keep_resident`, `MIDNIGHT_GPU_KEEP_KEYS`: by default the proving-key copies are freed at the end of a request; `evict_tables` frees them too
* `scripts/gpu-gate.sh`, the GPU gate (every device test including the 10,000-system quotient fuzz with its node coverage, and the kernel harness), and `examples/kernels.rs`, the kernel harness (every kernel at `2^14 ..= 2^21` against the CPU, MSM time for repeated, mostly zero and small scalars within 1.5 times the uniform time; a TSV)
### Changed
* The SRS table and proving-key copy checks are exact: every point of the caller's slice at every lookup, and the full digest of a key polynomial once per request (no sampled check)
* The quotient declines a coset shift that is not a primitive cube root of unity (reason `shape`), and gives every decline its reason (`unreduced` for a scalar not below the modulus)
* `end_request` folds the sticky erasure-failure count into its result
* A device block kept by both a failed release and a failed sppark teardown is one quarantine entry and one counted failure; a failed `cudaFree` of a crate buffer is counted once; the MSM bucket-row byte count is the copied width; `wipe::set_check` changes the Rust and core flags together; the core's test switches are compiled only into `test-fault` builds
* An explicit `MIDNIGHT_GPU_ARCHS` entry that the installed `nvcc` does not support fails the build; a default architecture left out prints a warning. `build.rs` reruns when `third_party/sppark` changes
* `MIDNIGHT_GPU_FAULT` set in a build without `test-fault` is refused (the device is not used)
* After a drain that could not be confirmed, the CUDA core keeps its page-locked bounce buffer and its read-back buffer as they are (not wiped, freed or handed out again; the copy takes the direct path) and counts an erasure failure, since a transfer may still target them
* Every error exit of a CUDA-core call that enqueued copies or kernels (copy, read-back, zeta, scale, periodic multiply, both MSM entry points, and the transform and quotient arms) drains its stream before it returns, so no transfer still reads or writes the caller's memory; drains and unconfirmed drains are counted (`error_drains()`)
* sppark patch: the MSM collector joins every started worker thread on every exit, a worker that throws wakes the collector, which throws after the join (the MSM returns an error), and the row sums and the worker and collector stacks are zeroed after use
* sppark patch: the error arms of the MSM (`msm_t::invoke`) drain every stream without throwing before the host vectors are freed, keep the vectors when a stream does not confirm (counted as an unconfirmed drain), and turn any other exception into an error code; the C entry points of the MSM and the NTT catch every exception, so none reaches Rust
* A quotient job with `k = 0` declines as `shape` in the header check (before the size gate and the device), not as a device error of the coset kernel
* A failed check-mode count of a zeroed device region (the call returned an error) is counted in `WipeStats::check_failures`, not in `device_nonzero`; the region is still kept in quarantine and counted as an erasure failure, and `end_request_report` fails on either. Fault point `check` (class `erase`) injects it
* `set_min_k` returns `false` and keeps the old value above `MAX_EXT_K`; such a `MIDNIGHT_GPU_MIN_K` is ignored
* Admission order: a quotient job with an unsupported coset shift declines as `shape` at every size (before the size gate); a one-element transform declines as `shape` before the CUDA core; an MSM longer than `2^MAX_MSM_LOG` (28) declines as `shape` before the device check (`msm_admission`). The quotient checks its header (ABI version, sizes, coset shift, minimum size) before the device check, so the stub declines with the same reasons; `field::primitive_cube_root`
### Removed
### Fixed
* `wipe::pending_erasure()` and `wipe::quarantined()` no longer wait for the quarantine lock: while a retry or a context reset holds it they answer at once with the last recorded counts, and the report has `reset_in_progress` set and is not clear. Diagnostics inside device operations and on the device-owner thread ignore a failed write to stderr, so it cannot turn a real decline into `operation-panic`, and on Linux they are appended through a fresh non-blocking descriptor of the process's stderr, without the standard stderr lock: a caller may hold that lock, or leave a stderr pipe undrained, while it waits for the device owner, so a line that cannot be written at once is dropped. A stderr that cannot be reopened (a socket) uses the standard stderr. A budget whose permit count exceeds `u32::MAX` saturates instead of wrapping
* Device-owner actor: releasing a proving-key copy no longer waits for the actor while the key registry is locked (a quotient on another thread could deadlock the device); teardown always runs on the actor once it exists, and a queued operation is dropped unrun on a retired device; a buffer dropped off the actor during teardown is counted exactly; a panic inside a device operation is its own decline reason (`operation-panic`) and the drain check still runs before the caller is released; after an unconfirmed drain a one-shot MSM context is not freed before the retirement
* A caller that asked for the device while the first request was still making the CUDA context could be told that there is no device and fall back to the CPU. The outcome of the first initialization is now published once, when it is complete; a caller that arrives earlier waits for it
* The size of the staging bounce buffer in the CUDA core is atomic: the statistics call (`xfer::stats`) reads it without the device lock while staged copies write it under the lock
* The injected read-back fault of the CUDA core exists only in `test-fault` builds: in every other build the fault argument of the private read-back has no effect
* Field values enter the kernel arguments of the coset kernels by `memcpy`, not by reading an `fr_t` through a pointer cast (strict aliasing)
* The error message of a failed sppark call is copied into the last-error text of the core and freed; the core takes ownership of that string, and it was leaked before
* A failed `cudaFree` of a public (non-witness) device buffer keeps the region in quarantine, counted once like a witness buffer, so `end_request` retries the free; before, the pointer was dropped and the free was never retried
* `wipe::pending_erasure()` reports what is still unerased (`PendingErasure`, `clear()`): the quarantined regions of this crate and their bytes, the sppark blocks of the CUDA core whose zeroing is not confirmed and their bytes, the blocks zeroed but not freed, and the zeroings whose synchronisation before the zeroing failed. In the core, a failed synchronisation before a zeroing no longer skips the memset: it is attempted, the block is kept as unconfirmed and the event is counted
* Test only (feature `test-fault`): `fault::fail_dev_frees`, `fault::fail_wipe_presync` and `fault::fail_lib_frees` make the next frees of this crate's device buffers, the next synchronisations before a zeroing, and the next frees after a confirmed zeroing fail in the CUDA core, so device tests drive the quarantine and the pending report through the real failure paths
* The device list of the vendored sppark is never destroyed: no CUDA stream or event is destroyed from a static destructor inside `exit()`, after the teardown of the CUDA runtime
* `teardown_ntt_tables()` frees the NTT twiddle tables explicitly under the device lock while the CUDA runtime is alive; the next transform builds them again. The tables no longer live in a function-local static object whose destructor ran inside `exit()`; a table is forgotten only after its own free succeeded, a throw between the allocations frees what was made, and the device is restored only when it was read
* An error drain that cannot be confirmed retires the device: before the device lock is released the CUDA context is reset, which ends every transfer that could still read or write host memory. `teardown::device_disabled()` and `teardown::erasure_failed()` are then sticky, every later device call declines with the reason `teardown` (`teardown::declined_after_teardown()`), and the library never exits the process. `teardown::teardown_context()` retires the device on request. Between the failed drain and the reset the core hands out no host buffer
* A context teardown zeroes every quarantined block once more before the reset and counts a block that is still unconfirmed when the reset takes it away (`wipe::PendingErasure::reset_unerased`, sticky): a reset frees device memory without zeroing it. `PendingErasure::undrained` is the count of unconfirmed drains that no reset has settled; `clear()` is false while either is non-zero. After the reset no device pointer is freed or used: buffers, MSM contexts and key copies are forgotten, the bounce buffer is zeroed before the reset and the read-back buffer after it
* A device call that waited for the device lock while another call reset the context declines instead of running on the dead context: the retired state is checked again once the lock is held
* A device-owner actor replaces the process-wide device lock: one dedicated thread owns the CUDA context and every device call is a typed request to it, answered on a per-request reply channel. The drain check and the retirement after an unconfirmed drain run on that thread before the reply is sent, and teardown is an actor operation that answers every queued and later request with the teardown decline, so no caller can run on a reset context. Requests, replies and the memory budget use std channels and condition variables (feature `actor`, enabled by `cuda`), so a caller's wait does not depend on an async runtime; a caller inside an async task blocks its thread for the call. The protocol is specified by a Quint model (`gpu-spec/quint/device_actor.qnt`) whose simulator traces replay against the protocol core (`actor::protocol`). Every operation class is exclusive in this version: the device sees the same sequence of calls as under the lock
